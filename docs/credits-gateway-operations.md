# Credits gateway operations

The gateway is OFF by default. The owner supplies `COLONY_CREDITS_UPSTREAM_KEY` in Fly secrets and explicitly sets `COLONY_CREDITS_GATEWAY=1` after release approval. The coordinator reported written OpenRouter product-pricing confirmation on 9 October 2026; this does not activate the flag. The default OpenRouter origin also accepts `OPENROUTER_MASTER_KEY`; that fallback is never sent to another provider host. Never put its value in a command transcript, source file or client configuration. A management-only key cannot perform inference. Apply migration `0055_account_ai_gateway.sql` before serving this version. Checkout providers need no change.

Server configuration selects `COLONY_CREDITS_UPSTREAM_BASE_URL` (HTTPS API base, default `https://openrouter.ai/api/v1`) and `COLONY_CREDITS_UPSTREAM_MODEL` (default `openai/gpt-4.1-mini` only for OpenRouter). Direct providers require an explicit model, reviewed allowlist entry and price table. `COLONY_CREDITS_MODEL_PRICES` is a JSON object keyed by model, with string fields `input_nanousd_per_million` and `output_nanousd_per_million`. For example, a synthetic entry is `{"direct-test-model":{"input_nanousd_per_million":"1000000001","output_nanousd_per_million":"2000000003"}}`. These are test prices, not vendor rates. Operators configure verified model rates before activation. OpenRouter without a price table requires returned cost or generation attribution; it never bills a price ceiling as actual token usage. Invalid configuration leaves capabilities disabled. Configuration changes fence recovery by a non-secret durable fingerprint. Restore the original configuration for generation-based operator corrections to old records.

`COLONY_CREDITS_ALLOWED_MODELS` is a JSON array of at most sixteen exact model ids. Its default is `["openai/gpt-4.1-mini"]`, whose OpenRouter route is pinned to OpenAI without fallback. Before adding a model, record a commercial-use Model Terms review for the model and its routing provider in the design note. Unlisted configured models disable the service. Customer request bodies cannot override model selection.

Request size is bounded: a managed-inference body may be up to 1 MiB (the other gateway routes take 64 KiB) and carry up to 1024 messages and 160 tools (the agent registers at most 128 MCP tools and adds one of its own). A Scout session sends about 47 KB of prompt and tool definitions before its first message and the agent keeps up to about 200k tokens of history, so smaller limits refuse ordinary sessions. The client drops the oldest whole turns when a conversation would not fit, and sends a line in place of any image. The hold for a request assumes the prompt can be no longer than the model's context window: `COLONY_CREDITS_MODEL_CONTEXT_TOKENS` (optional, default 262144, between 8192 and 312000). Set it to the server model's context window: the hold covers no more prompt than this, so a value below the real window under-holds, and a window above 312000 tokens cannot be covered. A model priced at zero still holds one nanousd.

An explicit `null` (or an empty list) for `tool_calls`, `tool_call_id` or `name` means the same as leaving it out, and is dropped before the request goes upstream: the shipped client sends `"tool_calls": null` on every system, user and tool message.

Every refusal is logged at `warn` with a fixed `check` name and no request content, key or value: `Colony gateway refused a managed inference request` (400, with `check`, `body_bytes`, `messages`, `tools`), `Colony gateway refused a request` (the other 400s, with `check` and `reason`) and `Colony gateway refused a request body over the route limit` (413). The inference checks are `request_parse`, `model_not_allowed`, `messages_empty`, `messages_over_limit`, `tools_over_limit`, `message_not_object`, `message_key_not_allowed`, `message_role`, `message_content`, `tool_calls_not_array`, `tool_calls_over_limit`, `tool_call_type`, `tool_shape`, `body_serialize`, `body_size`, `body_over_limit`, `price_table_missing`, `hold_price` and `hold_over_ledger_limit`. To see why a client was refused, search the relay log for `Colony gateway refused`. When the provider itself answers with an error status, the relay logs `Colony gateway upstream did not accept a request` with `upstream_status` (the status only, never the provider's body).

A provider 429 (common on free models, which are limited upstream) is retried inside the relay: at most 3 more times, after about 1 s, 2 s and 4 s plus up to 25% jitter. A provider `Retry-After` of 5 s or less is honoured when it is longer than the backoff; a longer one is ignored. Every attempt and wait of one request shares a 90 s budget, 10 s inside the managed client's 100 s request timeout, and no retry starts unless its wait and a 5 s attempt fit what is left. A 429 means the provider generated nothing: nothing is billed, the hold is unchanged, and the request settles once on eventual success. When it stays limited the request is refused exactly as before and the hold is released. Each refused try logs `Colony gateway upstream rate limited a request` with `attempt` and `upstream_status` (never the body). No other status is retried by the same model; with a fallback chain a 429 also moves the request to the next model (see Fallback model chain below).

OpenRouter additionally requires `COLONY_CREDITS_USER_HASH_KEY`, an independent server-only environment secret with at least 32 bytes of owner-generated entropy. It keys the stable HMAC of the payer account UUID sent as OpenRouter's `user`; the inference key is never the HMAC key. Missing or short tracking configuration leaves the gateway unavailable. Keep it stable across server replicas and inference-key rotations. Neither account ids, email, names nor the tracking secret are returned in gateway responses or logged. The owner supplies secrets through Fly; never request or inspect their values.

The current transport uses OpenAI-compatible `/chat/completions` and `prompt_tokens`/`completion_tokens`. Native Anthropic request/response support needs an additional adapter. Token-only direct responses settle from the configured table with one upward rounding after summing both token classes and adding twenty percent. Returned `usage.cost` takes precedence; invalid cost never silently falls back. Direct providers without a generation lookup retain the bounded provisional recovery policy. Automatic recovery never sends their generation ids to OpenRouter. Additional provider-specific reconciliation adapters remain necessary for their post-timeout corrections.

`GET /api/credits-gateway/capabilities` reports whether the relay can admit requests. Session creation requires an owner NIP-98 signature with a payload hash and an existing agent ownership record. A session lasts two hours, is bound to the community host and agent signer, and can be revoked through `/sessions/revoke`. The launch integration must replace its authorization before expiry.

Definite upstream validation, authentication, payment or rate-limit rejection settles zero usage and releases its hold immediately. Ambiguous responses keep their durable recovery record.

Once a request is admitted, the provider call and its settlement run on their own task, so a client that disconnects mid-request (an app quit or killed while waiting) cannot strand the hold: the answer is still read and settled at the provider's own cost, and the app's retry of that request id is refused as already charged. Only the relay process itself going away mid-request leaves a pending record for the recovery worker below.

Automatic recovery runs every 15 seconds, claims at most 16 records with database locks and durable exponential backoff, and makes at most four simultaneous generation lookups. Lookup attempts have ten-second deadlines. After fifteen minutes, absent attribution settles provisionally at the original maximum. Admission also settles at most four expired holds for its payer, so a worker backlog cannot strand a returning person. Records persist as `estimated`, and a structured warning identifies each request for review. The maximum hold is under $0.40 per request, at most four unresolved requests per payer, and one per session. The maximum is calculated from the private text/tool body, input framing allowance, 4096 output tokens and enforced OpenRouter price ceilings. Success always settles returned cost or configured token usage cost plus twenty percent before releasing completion content.

Operators investigate `account_ai_requests` rows with `status = 'estimated'`. Use `colony credits reconcile-ai --request-id <uuid> --generation-id <OpenRouter-generation-id>` with existing relay operator credentials supplied by the deployment environment. This signs the body with NIP-98 and asks `/api/credits-gateway/reconcile` to retrieve actual usage itself. Only `RELAY_OPERATOR_PUBKEYS` signers may correct records. A known generation id cannot be replaced, and a generation id cannot fund two journals. For a missing generation id, the operator must establish attribution from OpenRouter's account activity before assigning it. No customer may assign it. Repeating the correction cannot issue another refund. A cost above the authorized hold requires review and cannot overdraw the payer. Never repeat the original inference as a recovery step.

Pending holds reduce the existing balance read as negative adjustment rows. Final usage is a usage debit, paired with a hold release. An estimated charge corrected downward has one refund row. All financial mutations use the existing account row lock. Do not delete pending journals or manually remove their ledger holds. No prompt or completion is stored by this gateway; billing records retain usage counts, exact returned decimal cost, provider generation id, request digest and the margin-inclusive debit.

Release proof still requires fake-upstream GitHub CI, the managed-agent wiring PR, the flag/capability UI PR, deployment adoption and an owner-funded real reply. A green relay PR alone does not make Colony credits work in the desktop app.

## Free-AI accounts and the global daily cap (C3-JUDGE-AI)

Three optional relay environment variables. All are read once at startup; none is ever sent to a client.

- `COLONY_FREE_AI_ACCOUNTS`: comma-separated verified account emails (at most 64, case-insensitive, exact match). Those accounts use the gateway with no credit balance. Admission skips the balance check and writes no hold, release or usage rows to `account_credit_ledger`, so a free account never shows a negative balance and a debit can never fail. Each request is still metered in `account_ai_requests` (reserved and charged nanoUSD, generation id, usage) and logged as `Free Colony AI usage metered`. Settlement decides this from durable rows (a request with no ledger hold is journal-only), so removing an account from the list mid-flight cannot corrupt an admitted request. Every other account is governed exactly as before.
- `COLONY_FREE_AI_MAX_IN_FLIGHT`: unresolved requests a free account may hold at once, 1 to 256, default 32. Regular accounts keep four. Several devices signed in to one free account each hold their own session (one in-flight request per session), and a free account may hold 128 live sessions instead of 16.
- `COLONY_CREDITS_GLOBAL_DAILY_CAP_NANOUSD`: total gateway spend per UTC day across all accounts, free included, in margin-inclusive nanoUSD (the same unit as the ledger, so actual OpenRouter cost is about this divided by 1.2). Unset or empty means no cap. Admission counts settled and estimated rows at what they charged and pending rows at their hold, and refuses a request whose hold would pass the cap with HTTP 503 and `{"code":"daily_limit"}`. The check runs under one deployment-wide advisory lock, so concurrent payers cannot overshoot together. A value that is set but not a positive integer fails closed: all new inference is refused until it is corrected. Replays of finished work are not new spend and are never refused by the cap. There is no per-account hourly spend cap in this codebase; for the free account the daily cap is the runaway guard.

`GET /api/credits-gateway/access` (NIP-98 signed by the account owner) answers `{"freeAi": true|false}` for the caller's own account only, and `false` whenever the gateway is off. `GET /api/credits-gateway/capabilities` adds `freeAiConfigured`, a boolean that reveals no account.

## Fallback model chain (C3-JUDGE-AI-8)

A free model is often rate limited by its provider, or gone (OpenRouter free models carry an `expiration_date`). On 28 Oct the judge account saw "Connect your AI" because `poolside/laguna-s-2.1:free` answered 429 four times and the request ended in a 503. The relay can now try the next model instead.

- `COLONY_CREDITS_UPSTREAM_FALLBACK_MODELS`: optional JSON array of exact model ids (at most 7), tried in order after `COLONY_CREDITS_UPSTREAM_MODEL`. Unset or blank means one model, exactly as before. Each id must be in `COLONY_CREDITS_ALLOWED_MODELS` (so that list names the primary and every fallback, and the Model Terms review above applies to each), may not repeat or equal the primary, and needs an entry in `COLONY_CREDITS_MODEL_PRICES` wherever that table is set (always, for a direct provider). Anything wrong anywhere leaves the gateway off, like every other bad setting. The chain shares `COLONY_CREDITS_MODEL_CONTEXT_TOKENS` (default 262,144), so use models whose window is at least that.
- Recommended chain, free with tool support in `https://openrouter.ai/api/v1/models` on 28 Oct 2026:
  - `COLONY_CREDITS_UPSTREAM_MODEL=poolside/laguna-s-2.1:free`
  - `COLONY_CREDITS_UPSTREAM_FALLBACK_MODELS=["thinkingmachines/inkling:free","nvidia/nemotron-3-ultra-550b-a55b:free","google/gemma-4-31b-it:free","poolside/laguna-xs-2.1:free"]`
  - `COLONY_CREDITS_ALLOWED_MODELS=["poolside/laguna-s-2.1:free","thinkingmachines/inkling:free","nvidia/nemotron-3-ultra-550b-a55b:free","google/gemma-4-31b-it:free","poolside/laguna-xs-2.1:free"]`
  - Both `poolside/laguna-s-2.1:free` and `poolside/laguna-xs-2.1:free` list `expiration_date` 2026-10-31. An expired model answers 404 and the request moves on, so nothing breaks on that day, but replace them afterwards.
- The chain is walked in order with no wait between models. A 429, a 404, a 400 that says the model id is not valid, or a 5xx moves the request to the next model at once. Any other refusal (400, 401, 402, 403, 413, 422) is about the key, the price ceiling or the request and would fail on every model, so it ends the request. A transport failure or timeout also ends it, as before.
- When models were only rate limited, the same 1 s, 2 s, 4 s backoff waits and the walk repeats over those models, inside the same 90 s budget. Attempts per request are capped at 3 plus the number of models in the chain, so a limit shared by every model costs a few calls, not one per model per retry. A model that was gone or answered 5xx is not asked again by that request.
- When every model fails the request ends as a single model does: all 429 or 404 is the usual 503 and the hold is released; any 5xx in the walk leaves the hold to the durable recovery worker.
- The charge, the stored usage (`account_ai_requests.usage.model`) and the response `model` name the model that answered, and its own price (token table) or returned cost decides the charge. A free model stays zero cost. For a direct provider the hold covers the dearest model in the chain. The request fingerprint names only the primary model, so adding or changing fallbacks does not fence recovery of requests in flight.
- Only `openai/gpt-4.1-mini` is pinned to the OpenAI provider. A fallback is sent its own `model`, and the pin follows that model alone.
- 429 reason code. `Colony gateway upstream rate limited a request` carries `model`, `attempt` (the request's upstream call count, from 1), `upstream_status` and `reason`, one of: `free_models_per_day`, `free_models_per_minute`, `account_rate_limited` (OpenRouter's limit on the whole account), `provider_rate_limited` (one provider is busy), `unknown`. The code is read from the error body and the `X-RateLimit-Limit` header and never logs either. `Colony gateway answered from a fallback model` (info) shows when a fallback answered.
- All `:free` models share one OpenRouter account limit (20 requests per minute, and 50 per day, or 1000 per day with at least 10 credits bought). The chain fixes a busy provider, not that account cap: when the log shows `free_models_per_day`, `free_models_per_minute` or `account_rate_limited`, a different model will not help. Buy credits on the OpenRouter account or wait for the reset.
