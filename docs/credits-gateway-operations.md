# Credits gateway operations

The gateway is OFF by default. The owner supplies `COLONY_CREDITS_UPSTREAM_KEY` in Fly secrets and explicitly sets `COLONY_CREDITS_GATEWAY=1` after release approval. The coordinator reported written OpenRouter product-pricing confirmation on 9 October 2026; this does not activate the flag. The default OpenRouter origin also accepts `OPENROUTER_MASTER_KEY`; that fallback is never sent to another provider host. Never put its value in a command transcript, source file or client configuration. A management-only key cannot perform inference. Apply migration `0055_account_ai_gateway.sql` before serving this version. Checkout providers need no change.

Server configuration selects `COLONY_CREDITS_UPSTREAM_BASE_URL` (HTTPS API base, default `https://openrouter.ai/api/v1`) and `COLONY_CREDITS_UPSTREAM_MODEL` (default `openai/gpt-4.1-mini` only for OpenRouter). Direct providers require an explicit model, reviewed allowlist entry and price table. `COLONY_CREDITS_MODEL_PRICES` is a JSON object keyed by model, with string fields `input_nanousd_per_million` and `output_nanousd_per_million`. For example, a synthetic entry is `{"direct-test-model":{"input_nanousd_per_million":"1000000001","output_nanousd_per_million":"2000000003"}}`. These are test prices, not vendor rates. Operators configure verified model rates before activation. OpenRouter without a price table requires returned cost or generation attribution; it never bills a price ceiling as actual token usage. Invalid configuration leaves capabilities disabled. Configuration changes fence recovery by a non-secret durable fingerprint. Restore the original configuration for generation-based operator corrections to old records.

`COLONY_CREDITS_ALLOWED_MODELS` is a JSON array of at most sixteen exact model ids. Its default is `["openai/gpt-4.1-mini"]`, whose OpenRouter route is pinned to OpenAI without fallback. Before adding a model, record a commercial-use Model Terms review for the model and its routing provider in the design note. Unlisted configured models disable the service. Customer request bodies cannot override model selection.

OpenRouter additionally requires `COLONY_CREDITS_USER_HASH_KEY`, an independent server-only environment secret with at least 32 bytes of owner-generated entropy. It keys the stable HMAC of the payer account UUID sent as OpenRouter's `user`; the inference key is never the HMAC key. Missing or short tracking configuration leaves the gateway unavailable. Keep it stable across server replicas and inference-key rotations. Neither account ids, email, names nor the tracking secret are returned in gateway responses or logged. The owner supplies secrets through Fly; never request or inspect their values.

The current transport uses OpenAI-compatible `/chat/completions` and `prompt_tokens`/`completion_tokens`. Native Anthropic request/response support needs an additional adapter. Token-only direct responses settle from the configured table with one upward rounding after summing both token classes and adding twenty percent. Returned `usage.cost` takes precedence; invalid cost never silently falls back. Direct providers without a generation lookup retain the bounded provisional recovery policy. Automatic recovery never sends their generation ids to OpenRouter. Additional provider-specific reconciliation adapters remain necessary for their post-timeout corrections.

`GET /api/credits-gateway/capabilities` reports whether the relay can admit requests. Session creation requires an owner NIP-98 signature with a payload hash and an existing agent ownership record. A session lasts two hours, is bound to the community host and agent signer, and can be revoked through `/sessions/revoke`. The launch integration must replace its authorization before expiry.

Definite upstream validation, authentication, payment or rate-limit rejection settles zero usage and releases its hold immediately. Ambiguous responses keep their durable recovery record.

Automatic recovery runs every 15 seconds, claims at most 16 records with database locks and durable exponential backoff, and makes at most four simultaneous generation lookups. Lookup attempts have ten-second deadlines. After fifteen minutes, absent attribution settles provisionally at the original maximum. Admission also settles at most four expired holds for its payer, so a worker backlog cannot strand a returning person. Records persist as `estimated`, and a structured warning identifies each request for review. The maximum hold is under $0.40 per request, at most four unresolved requests per payer, and one per session. The maximum is calculated from the private text/tool body, input framing allowance, 4096 output tokens and enforced OpenRouter price ceilings. Success always settles returned cost or configured token usage cost plus twenty percent before releasing completion content.

Operators investigate `account_ai_requests` rows with `status = 'estimated'`. Use `colony credits reconcile-ai --request-id <uuid> --generation-id <OpenRouter-generation-id>` with existing relay operator credentials supplied by the deployment environment. This signs the body with NIP-98 and asks `/api/credits-gateway/reconcile` to retrieve actual usage itself. Only `RELAY_OPERATOR_PUBKEYS` signers may correct records. A known generation id cannot be replaced, and a generation id cannot fund two journals. For a missing generation id, the operator must establish attribution from OpenRouter's account activity before assigning it. No customer may assign it. Repeating the correction cannot issue another refund. A cost above the authorized hold requires review and cannot overdraw the payer. Never repeat the original inference as a recovery step.

Pending holds reduce the existing balance read as negative adjustment rows. Final usage is a usage debit, paired with a hold release. An estimated charge corrected downward has one refund row. All financial mutations use the existing account row lock. Do not delete pending journals or manually remove their ledger holds. No prompt or completion is stored by this gateway; billing records retain usage counts, exact returned decimal cost, provider generation id, request digest and the margin-inclusive debit.
