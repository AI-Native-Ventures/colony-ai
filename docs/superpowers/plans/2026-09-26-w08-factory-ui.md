# W08 Software Factory UI Implementation Plan

> **For agentic workers:** This plan is executed inline in the approved W08 Factory UI worktree. Steps use checkbox syntax for tracking.

**Goal:** Add the r19 Software Factory destination and its projects, plans, sessions, review, and state routes, using real scoped Factory runs and no production fixture records.

**Architecture:** Register a dedicated `/factory` route family and add the Software Factory entry to the existing workspace sidebar. Build screens from existing relay-backed projects, host-scoped Factory commands, and user-created local plan records keyed by relay, identity, business, and optional client. Keep only test fixtures in Playwright setup.

**Tech Stack:** React 19, TanStack Router, React Query, Tauri IPC Factory runtime, TypeScript, Tailwind, Playwright.

## Task 1: Register the standalone Factory destination

**Files:** the app and sidebar files listed above, plus `desktop/src/app/routes.ts` and new route entry files.

- [ ] Add `factory` to `AppView` and `SidebarSelectedView`. Make `deriveShellRoute()` return `factory` for `/factory` and every `/factory/...` path.
- [ ] Add `goFactory()` in `useAppNavigation()` and route the `Software Factory` sidebar button to it.
- [ ] Hide `AppTopChrome` on Factory routes. Keep the existing sidebar and render `FactoryWorkspace` with the r19 header and route content.
- [ ] Register `/factory`, `/factory/projects`, `/factory/plans`, `/factory/plan/$planId`, `/factory/project/$projectId`, `/factory/review/$runId`, `/factory/sessions`, and `/factory/states` in `routes.ts` and add small route files that pass the route identifier to `FactoryWorkspace`.
- [ ] Keep `/projects` registered. Give legacy project tests a visible route through the existing sidebar Projects action instead of retargeting their assertions to a different screen.
- [ ] Add unit tests for `deriveShellRoute()` covering `/factory`, all Factory descendants, `/projects`, and `/projects/$projectId`.

The Factory route state has this shape:

```ts
export type FactoryPageRoute =
  | { kind: "workbench" }
  | { kind: "projects" }
  | { kind: "project"; projectId: string }
  | { kind: "plans" }
  | { kind: "plan"; planId: string }
  | { kind: "review"; runId: string }

```

## Task 2: Bind the UI to host-scoped Factory runs

**Files:** add `desktop/src/features/factory/useFactoryRuns.ts`, status helpers, tests, and use existing `desktop/src/shared/api/factoryRuntime.ts` without passing renderer-selected scope to commands.

- [ ] Create `useFactoryRuns()` around `listFactoryRuns()`. Reattach every listed run with `reattachFactoryRun()` and merge snapshots by run id and event sequence.
- [ ] Detach every attachment on route unmount and never call `cancelFactoryRun()` from a pane or route close path.
- [ ] Refresh the run list after scoped events and explicit retry. Preserve the last successful snapshot if a reattach fails, and expose the failure for the designed error or reconnect view.
- [ ] Add `cancelRun(runId)` using only `cancelFactoryRun()`. Refresh the list after it succeeds.
- [ ] Add production-path tests for event-driven snapshot refresh, scope changes clearing old data, detach preserving active runs, and blocked, waiting, error, done, and cancelled status labels.

The public hook result is:

```ts
export type FactoryRunsResult = {
  runs: FactoryRun[];
  snapshots: ReadonlyMap<string, FactoryRunSnapshot>;
  loading: boolean;
  error: Error | null;
  refresh: () => Promise<void>;
  cancelRun: (runId: string) => Promise<void>;
};
```

## Task 3: Render real project and session routes

**Files:** project, session, review, and workbench screens under `desktop/src/features/factory/ui/`; E2E test fixture and route specs.

- [ ] Use `useProjectsQuery()` for project list and detail. Match Factory run `projectId` to existing project ids and show only the run counts derived from the host list.
- [ ] Use `useProjectLocalRepositoriesQuery(activeCommunity?.reposDir)` to resolve selectable checkout paths. Do not clone, scan, or execute a repository as a render side effect.
- [ ] Use `useManagedAgentsQuery()` to populate only local managed agents. Pass the selected agent pubkey, repository id, project id, checkout path, parent run id, prompt, and idempotency key to `createFactoryRun()`.
- [ ] Render the session directory from host runs and filter from actual statuses. Render the status route from actual selected runs and reattach failures, including the host's persisted blocked state after interruption. Do not synthesize status transitions in production.
- [ ] Render run output from `FactoryRunSnapshot.events`, retain the per-run draft with `setFactoryRunDraft()`, and cancel only from an explicit run action.
- [ ] Add tests proving project counts, project session context, status filters, snapshot output, explicit cancel, and reattach failure all use runtime responses rather than production sample data.

## Task 4: Render plan and review routes without sample records

**Files:** `factoryPlanStore.ts`, plan and review screens, pure module tests, and route E2E tests.

- [ ] Key plan storage by the full active relay, identity pubkey, business id, and optional client id. Store only plans the user creates through the UI; start from an empty collection.
- [ ] Support create and edit plan, acceptance criteria, task dependencies, revisions, and the visible plan status used by the r19 list and detail screens. Catch storage errors and keep the editor open when a save fails.
- [ ] Bind project details to relay-backed project data and run details to host-backed run snapshots. A review route must show only actual run output or repository diff data already available through project APIs.
- [ ] Do not publish fake review approvals, checks, pull requests, or agent assignments. Disable an action only when its current real prerequisite is false; do not create a mock result.
- [ ] Test full-scope plan isolation, reload persistence, revision behavior, and a failed storage write through the production store.

Plan records use this shape:

```ts
export type FactoryPlan = {
  id: string;
  projectId: string;
  title: string;
  outcome: string;
  acceptanceCriteria: string[];
  tasks: FactoryPlanTask[];
  revisions: FactoryPlanRevision[];
  status: "draft" | "review" | "approved";
  updatedAt: string;
};
```
