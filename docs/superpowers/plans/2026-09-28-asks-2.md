# Asks 2 Implementation Plan

> **For agentic workers:** This plan is executed inline by the asks-2 worker. The coordinator remains the sole integrator.

**Goal:** Implement ask creation from a thread composer and message action, grouped Needs me views, and record-backed specialised ask details against the frozen company v8 reference.

**Architecture:** Keep the existing kind 47032 and kind 30643 record contract. A pure composer module validates and builds an ask action. The create screen signs that action once, retains it through a publish failure, and retries the same event. Needs me grouping remains a projection of the existing deadline-sorted queue. Specialised views are selected only from fields on a verified ask head.

**Tech Stack:** React 19, TypeScript, TanStack Router, TanStack Query, Nostr signed events, Playwright mock bridge, Node unit tests.

---

## Acceptance Gate

- Composer and message actions open one create screen with the source channel and thread root.
- All five ask types validate their type-specific fields; recipient selection includes channel people and AI employees.
- A rejected send keeps the draft and signed event. Retry publishes that same event once and opens the ask's individual detail route.
- Needs me supports deadline, type, and channel grouping, overdue records, show more, and empty data without changing the source order or dropping records.
- Money, tool, and hire approvals render a distinct card label only when the verified head carries that category and approval type.
- The frozen v8 route appearance is compared at 1728x1117 and 1440x900 in light and dark themes.
- Focused local checks stay within the supplied quick-check limits. The draft PR is complete only after hosted checks are green.

1. Add the pure ask draft validator and create-action builder. Cover approval, question, choice, checklist, verdict, invalid option counts, required fields, and stable action identity in unit tests.
2. Add the routed create screen. Load people and AI employee identities from existing channel and relay queries. Sign once, keep the event after rejection, guard concurrent submission, and navigate to `/asks/$channelId/$askId` after acknowledgement.
3. Add composer and message-menu entry points. Derive the root from the active thread or message tags and pass it into the create route. Preserve all existing message menu actions and test identifiers.
4. Add grouping projections and UI. Group the complete already-sorted item set by deadline, ask type, or channel. Keep workflow approvals in the queue, keep rows deadline ordered within groups, and keep expansion state when grouping changes.
5. Add a pure specialised-card mapper and render only record-backed money, tool, and hire approval labels. Leave unavailable record families unreachable and report them under `NEEDS_API`.
6. Extend the mock bridge and E2E coverage for both entry points, rejected publish followed by identical retry, and grouping changes. Update every affected locator in the same change.
7. Run only quick checks for touched desktop files, capture and compare the frozen routes at both required sizes and themes, commit with signoff, push, open a draft PR against `codex/phase2-integration`, and resolve hosted CI failures until all checks are green.
